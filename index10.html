★ Certificate of Merit · Hackathon 2026

EV Fleet Charging Orchestration Platform

A charging control room for companies that run electric vehicle fleets: buses, delivery trucks and vans. Admins see every vehicle and charger live, the system shares limited grid power between them, and drivers check their charging status from their phone.

ReactTypeScriptFirebase FirestoreTailwind CSSVite
Built for the LBRCE Hackathon 2026, Full Stack Development track

See the team award photo

  • loadSmart load sharing. Keeps total charging under the depot's grid limit and hands out power by policy: first come first served, buses first, lowest battery first, or equal share.
  • liveReal-time sync. Built on Firestore, so a change in one browser (a new vehicle, a tariff update, an invoice) shows up instantly in every open window.
  • billBilling in rupees. Peak and off-peak tariffs per kWh, with GST tax invoices generated for each charging session.
  • rolesThree admin levels and a driver portal. Super, fleet and site admins each see what they need; drivers get a mobile view of battery, timer and cost.

CityPulse

A mobile app for reporting problems in your city. A citizen takes a photo, drops a GPS pin and picks a category; the complaint goes to the right department automatically, and everyone can follow it on a live map until it is fixed.

FlutterDartFirebase AuthCloud FirestoreOpenStreetMap
View source code
  • mapLive complaint map. Every report is a pin on OpenStreetMap, coloured by status, with a tap-to-preview card.
  • dupesDuplicate detection. A report in the same category within 200 m offers a "me too" instead of creating a second complaint.
  • rankAutomatic priority. Scored from category weight, urgent keywords and supporter count, with a deadline set by priority.
  • rolesCitizen, officer and admin. Officers start work and resolve with a note and photo; citizens rate the fix or reopen it; admins see statistics and manage users.

CollectMind

An AI assistant for microfinance loan officers. Before visiting a borrower, the officer gets a short brief built from every past visit: who pays after harvest, whose promises break, and which approach actually worked.

PythonFastAPIHindsight memoryGroq LLMJavaScript
View source code

// the problem

Field officers visit 15 to 25 borrowers a day. What worked last time is usually lost in a paper diary, so every visit starts from zero.

// what I built

A FastAPI backend that saves every visit into long-term memory with dates and tags, then recalls it to write the next brief. A toggle shows the same brief with and without memory.

// what I learned

Handling LLM failures properly: retries, rate-limit backoff and a fallback model, so the app keeps working when one model doesn't.
